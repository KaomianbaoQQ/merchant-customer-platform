# 测试商城商户管理后台

给商户使用的后台界面，支持**多商户账号注册 / 登录**、任意商品上架、多图上传、
与顾客在线沟通。商品与客户前端共用同一套数据，商家上架后客户立即可见。

> 商户后台的页面与接口已统一到项目主后端（Flask）中，不再单独维护第二个服务。
> 知识库同步（Dify 等）已从界面移除，仅保留不可见的预留接口
> `syncKnowledgeBase()` → `POST /api/merchant/knowledge/update`。

## 快速开始

```bash
# 方式一：直接启动整套后端（客户 + 商户），默认 8000
.venv/bin/python main.py

# 方式二：沿用原命令启动，默认 8001
.venv/bin/python "商户界面/后端服务 server.py" 8001
```

- 商户后台：`http://127.0.0.1:<端口>/merchant`
- 客户前端：`http://127.0.0.1:<端口>/`

> 需要 Flask 与 PyMySQL，建议使用项目虚拟环境 `.venv`。
> 修改代码后请**重启后端**，否则浏览器仍会连到旧进程。

### 常见问题：页面报 “Load failed”

- **直接双击 html 文件打开（file://）**：浏览器无法请求相对路径的接口。
  现已支持：此时前端会自动把接口指向 `http://127.0.0.1:8000`；
  若后端跑在别的端口，用 `前端/商户界面.html?api=http://127.0.0.1:8001` 打开。
- **后端没启动 / 端口不对**：确认 `http://127.0.0.1:8000/merchant` 或
  `http://127.0.0.1:8001/merchant` 能打开，再操作。
- 推荐直接用后端提供的地址打开（同源最省事）：`http://127.0.0.1:8000/merchant`。

## 多商户账号

- 打开 `/merchant` 先进入登录页，可切换「注册」。
- 账号为**用户名 + 密码**，注册后写入数据库表 `cs.merchant`（密码加盐哈希存储）。
- 登录返回 token，前端保存在 `localStorage`，后续请求通过
  `Authorization: Bearer <token>` 鉴权。
- **每个商户只能看到 / 修改 / 删除自己上架的商品**，商品记录里保存了
  `owner_id / owner_name`，实现多商户隔离。
- 仓库内数据库已清空，没有预置商户与商品：在商户后台注册账号后自行上架即可。

## 商品管理

1. 名称、类目（任意填写，不限预置类型）、价格、描述、规格参数（可动态增删）。
2. 图片支持一次选择多张 / 拖拽上传，第一张自动作为封面，可逐张删除。
3. 保存 / 删除后，客户前端 `GET /api/products` 立即返回最新数据。

## 订单管理（查看全部订单 / 随时发货）

- 顶部「订单管理」标签页列出**本店商品的全部订单**，可按 `全部 / 待发货 / 已发货` 筛选。
- **快递单号由商家填写**：客户下单后订单进入「待发货」，商家在订单卡片里填写
  **7 位数字**快递单号并点「发货」，订单才写入 `cs.logistics` 并开始计算送达时间。
  - 商家填单后 `发货时间 = 当前时间`，`预计送达 = 当前时间 + 5 分钟`（`config.json` 的 `default_delay`）；
  - 物流状态与之前一致：已发货 → 运输中 → 派送中 → 已签收，5 分钟后自动签收。
  - 同一次结算的多件商品会一起发出（共用刚填写的运单号）。
- 订单卡片显示顾客、订单号、下单时间、金额、收货地址、运单号与状态；
  待发货可直接发货，已发货可一键「查询物流」。
- 「顾客消息」聊天窗口顶部也会显示**该顾客在本店的订单**，同样可以直接填写单号发货。

## 商品数据（浏览量 / 销量 / 买家 / 物流）

- 商品列表每一行显示 **浏览量** 与 **销量**；点「数据」打开右侧抽屉，查看：
  - 浏览量、销量（件）、订单数、买家数、销售额、单价；
  - **购买顾客**列表：每个顾客的购买次数、购买件数、消费金额；
  - 每笔订单的 **订单号 / 数量 / 物流状态 / 运单号**，可一键「查询物流」（弹窗展示）。
- 浏览量由客户前端打开商品详情时调用 `POST /api/products/<id>/view` 自动累加。
- 销量 / 销售额 / 买家来自订单表（`cs.order`）：下单时会写入 `product_id` 与 `price`，
  老订单没有 `product_id` 时按商品名兜底匹配。
- 「退款处理」页顶部搜索框也可输入运单号查询物流，接口 `GET /api/merchant/logistics?waybill=`。

## 退款处理

- 顾客在客户前端「我的订单」里，对**未收到货**的订单也能直接点「未收到货？申请退款」，
  **无需填写快递单号**；已签收的订单则同时提供退货 / 换货 / 退款。
- 退款申请进入商户后台的「退款处理」标签页，状态由商家处理驱动：
  `待商家处理 → 退回中 → 派送中 → 商家签收 → 已退款`，也可「拒绝」。
- 顾客端「我的订单」会同步显示这些状态；被拒绝的退款不计入已退数量，可重新申请。

## 顾客消息

- 客户前端「联系商家」的消息会进入对应商户的会话（按 `商户 + 顾客` 隔离）。
- 左侧会话列表显示顾客、最后一条消息、未读红点；右侧查看记录并回复。
- 顾客每条新消息都会触发顶部横幅、红点与提示音，提醒商家及时回复（商家真人回复后解除）。
- 顾客表达「退货 / 换货 / 退款」等意图时，会话亮「退换货意向」标签、聊天窗口顶部亮提醒条，
  横幅提示优先跟进；点击横幅优先跳到该会话。
- 顾客端每 4 秒轮询自动收到回复。

## 与客户前端的联动

- 客户前端商品数据来自 `GET /api/products`，不再写死。
- 商品带上 `owner_id / owner_name`，客户在商品页连续发送「人工」等关键词后，
  会自动转接到**该商品所属商家**的客服会话。
- 顾客留言写入 `商户界面/chat.json`，商户后台读取同一份文件。

## 接口一览（前缀 /api/merchant，除注册/登录外均需 token）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/register` | 商户注册（用户名 / 密码 / 姓名 / 店铺名） |
| POST | `/login` | 商户登录，返回 token |
| POST | `/logout` | 退出登录 |
| GET | `/me` | 当前登录商户 |
| GET | `/products` | 我的商品列表 |
| POST | `/products` | 新增商品 |
| PUT | `/products/<id>` | 修改商品（仅限本人商品） |
| DELETE | `/products/<id>` | 删除商品（仅限本人商品） |
| POST | `/upload` | 图片上传（multipart，可多次调用） |
| GET | `/products/<id>/orders` | 某商品的订单明细 + 买家汇总（购买次数/订单号/物流） |
| GET | `/orders?user_id=&status=` | 本店全部订单（可按顾客 / `pending`\|`shipped` 过滤） |
| POST | `/orders/<order_id>/ship` | 发货：`{"waybill":"1234567"}`，必须是 7 位数字 |
| GET | `/logistics?waybill=` | 按运单号查询物流 |
| GET | `/refunds` | 顾客提交的退款申请列表 |
| POST | `/refunds/<id>/status` | 处理退款（`status=next` 自动推进，或 requested/returning/delivering/received/refunded/rejected） |
| GET | `/chats` | 顾客会话列表 |
| GET | `/chats/thread?user_id=&merchant_id=` | 单个会话（读取后自动已读） |
| POST | `/chats/reply` | 回复顾客 |
| POST | `/knowledge/update` | 知识库同步（预留，暂未实现） |

客户后端（同一 Flask 应用）另提供：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/products` | 客户前端读取全部商家商品 |
| POST | `/api/products/<id>/view` | 商品浏览量 +1（客户前端打开详情时调用） |
| POST | `/api/register` `/api/login` | 客户注册 / 登录 |
| POST | `/api/orders` | 下单（写 `cs.order`，订单先进入「待发货」，运单号由商家发货时填写） |
| POST | `/api/returns` | 申请退货 / 换货 / 退款（`return_type=refund` 无需签收、无需快递单号） |
| POST | `/api/chat` | 顾客留言（带 merchant_id） |
| GET | `/api/chat?user_id=&merchant_id=` | 顾客拉取商家回复 |
